# Interface languages

Lumina supports **English** (default) and **Tiếng Việt**. Use the language selector in the top bar or on the sign-in page. The choice is stored in this browser under `lumina.locale` and synchronized across tabs. Missing/invalid/blocked storage falls back to English; switching still works in memory when storage is blocked.

Changing the interface language does not reload the page or translate project names, prompts, scripts, dialogue, character profiles, AI replies, model IDs, or provider diagnostics. Content-generation language remains independently configured.

## Development

- Runtime: `src/i18n`, dependency-free React external locale store.
- Catalogs: `src/i18n/catalogs`, semantic keys with `{ en, vi }` pairs.
- React: `const { t, locale } = useTranslation(catalog)`; translate during rendering, not at module import.
- Errors: API envelopes retain `code/message/details` and add `messageKey/messageParams`; resource errors expose `errorMessageKey/errorMessageParams`. Raw technical diagnostics remain available separately.
- Persistence: migration 015 adds nullable metadata columns without modifying user content.
- Tests: `pnpm run check:i18n`, `pnpm run typecheck`, `pnpm run test:backend`, `pnpm run test:e2e`.
- Legacy E2E flows explicitly use Vietnamese storage; the dedicated i18n suite starts with clean storage and verifies English default, switching, persistence, multi-tab synchronization, errors, and mobile layout.

Every new app-owned label, tooltip, accessibility label, status, or message must have both translations. Keep enum/API values locale independent and interpolate user data without translating it.
